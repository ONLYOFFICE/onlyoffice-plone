# HANDOVER — onlyoffice.plone

Backend add-on connecting Plone to ONLYOFFICE Docs. Companion repo: `onlyoffice-volto`
(Volto frontend add-on, needs this package on the backend). Day-to-day commands: `CLAUDE.md`.
Release procedure: `.claude/skills/release/SKILL.md`.

## 1. Integration type

- **Embedded add-on**: Python package `onlyoffice.plone` installed into the Plone backend (Zope).
  Loaded by `plone.autoinclude` (entry point in `setup.py`), activated per site in
  Site Setup → Add-ons (GenericSetup profile `onlyoffice.plone:default`).
- Two UIs, one backend:
  - **Classic UI** — browser views and `.pt` templates in `browser/`;
  - **Volto** — REST services `@onlyoffice-volto-*` in `restapi/`, called by `@onlyoffice/volto`.
- Talks to **ONLYOFFICE Docs (Document Server)** only:

  | Direction | What | Code |
  |---|---|---|
  | Browser → Docs | `web-apps/apps/api/documents/api.js?shardkey=<key>`, `DocsAPI.DocEditor` | `templates/view.pt` |
  | Docs → Plone | download file: `GET <file>/onlyoffice-dl/file?token=…` | `api.py:ODownload` |
  | Docs → Plone | callback: `POST <file>/onlyoffice-callback?token=…`, status 2/3 = save | `api.py:Callback` |
  | Plone → Docs | Conversion API `POST converter?shardkey=<key>` | `core/conversionUtils.py` |
  | Plone → Docs | `healthcheck`, Command Service `c=version` (settings validation only) | `controlpanel.py` |
  | Docs → Plone | `onlyoffice-test-convert` (test file for the ConvertService check) | `api.py:OTestConvert` |

- Supported versions:
  - **Plone 6.1** is declared in `setup.py` and README; the tox matrix also lists 6.0 and 6.2 but CI does not run tests.
    Python `>=3.9` (classifiers 3.9–3.11). Smoke tests pass on Plone 6.1.6 / Python 3.12.
  - **ONLYOFFICE Docs**: the editor page still rejects only Docs ≤ 6.0, which is outdated. Current features need more:
    the format table opens PDFs with `documentType: "pdf"` (Docs API **8.0**+), and `shardkey` was added in Docs API **8.1**
    (both per the Docs API changelog). **Practical minimum: Docs 8.1.** End-to-end smoke test passes on Docs 10.0.
- Repositories: work and PRs happen on `git.onlyoffice.com/ONLYOFFICE/onlyoffice-plone` (`origin`);
  `github.com/ONLYOFFICE/onlyoffice-plone` is the public mirror where GitHub Actions (lint, licenses, tag, release) run.

## 2. Main features

| Scenario | Classic UI | Volto | Code |
|---|---|---|---|
| Edit in ONLYOFFICE, co-editing, save via callback | "ONLYOFFICE Edit" action | yes | `actions.py:Edit`, `api.py:Callback` |
| View (user can view but not modify) | "ONLYOFFICE View" action and display view | yes | `actions.py:View` |
| Review (can review, cannot modify) | "ONLYOFFICE Review" | yes | `actions.py:Review` |
| Fill PDF forms | "Fill in form in ONLYOFFICE" | yes | `actions.py:FillForm` |
| Create Document / Spreadsheet / Presentation / PDF form from a localized template | "Create with ONLYOFFICE" menu | yes | `api.py:Create`, `menu.py` |
| Download as (convert + download) | "Download as" | yes | `api.py:DownloadAs` |
| Convert to OOXML, result saved next to the source | "Conversion in ONLYOFFICE" | no | `api.py:Conversion` |
| Save copy as (from the editor) | yes | no | `view.pt`, `api.py:SaveAs` |
| Insert image / compare file / mail merge from Plone | yes | no | `view.pt`, `api.py:OInsert` |
| Settings: Docs URL, JWT secret, internal URLs, 30-day demo server, connection validation | control panel | yes | `controlpanel.py`, `restapi/post.py` |

What each format supports (view / edit / fill / convert targets) comes from the `document-formats` submodule.

## 3. Build

- **Submodules are mandatory** — without them the package is broken:
  - `browser/app_data` ← `ONLYOFFICE/document-templates`, branch `main/new-2letter-code` (new-file templates per language);
  - `browser/document-formats` ← `ONLYOFFICE/document-formats` (format table).
- **sdist**: `python -m build`. Non-standard step: CI deletes `.git/`, `.gitignore`, `.gitmodules` before building,
  otherwise the submodule files are not packed. Do the same in a throw-away clone when building by hand.
- Toolchain: Python 3.9 for build/release in CI, 3.12 for lint; `setuptools>=68.2,<=80.9.0`.
- Lint/tox/pre-commit configs are generated by `plone/meta` (`.meta.toml`); edit `.meta.toml`, then regenerate.
- No private dependencies. `PyJWT` and `requests` are imported but not declared in `install_requires`
  (they come with Plone).
- `z3c.jbot==2.0` is pinned in `setup.py` while Plone 6.1 constraints pin 3.1: `pip install -c <plone constraints> onlyoffice.plone`
  fails with `ResolutionImpossible`. Installing without constraints (Docker `ADDONS`/`DEVELOP`, plain pip) works.

### Local stand (Plone + Docs, Docker)

```bash
docker network create ooplone
docker run -d --name docs --network ooplone -p 8081:80 \
  -e JWT_ENABLED=true -e JWT_SECRET=<test secret> \
  -e ALLOW_PRIVATE_IP_ADDRESS=true \
  onlyoffice/documentserver:latest        # or documentserver-de / -ee
docker run -d --name plone --network ooplone -p 8080:8080 \
  -e SITE=Plone -e TYPE=classic -e PROFILES=onlyoffice.plone:default \
  -e DEVELOP=/app/src/onlyoffice.plone -v "$PWD:/app/src/onlyoffice.plone" \
  plone/plone-backend:6.1 start
```

- `ALLOW_PRIVATE_IP_ADDRESS=true` is required: by default Docs refuses to download files from private IPs (other containers).
- Settings (control panel): Docs address `http://localhost:8081/` (as the **browser** sees it),
  Docs address for internal requests `http://docs/`, server address for internal requests `http://plone:8080/`
  (Plone root, **without** the site id — the site path is appended by the add-on). Secret = the JWT secret above.
- Default admin user of the Plone image is in the image docs; first start takes a few minutes (pip install of the add-on).
- `TYPE=volto` creates a Volto site; the frontend is set up as described in `onlyoffice-volto/HANDOVER.md`.

## 5. Implicit knowledge

- **Document key** = `base64(obj.id + "_" + modification_date)` (`core/utils.py:getDocumentKey`), not the UUID
  as the README says. It changes on every save and on rename.
- **The callback saves through `reindexObject()` without arguments.** That call runs `notifyModified()`, which bumps
  `modification_date` and therefore the key. With `reindexObject(idxs=[...])` the key stays the same and Docs serves the cached old version.
- **URL `?token=`** on `onlyoffice-dl` / `onlyoffice-callback` is a JWT signed with the object UUID, payload `{"key": obj.id}`.
  These views are `zope2.Public` (Docs has no user session), so the tokens (plus the Docs JWT, when enabled) are their only protection.
- **JWT** is on when a secret is set (or the demo is active). Header name comes from env `ONLYOFFICE_JWT_HEADER`
  (default `Authorization`); the demo server uses `AuthorizationJWT`. JWT payload expires after 24 h.
- **Demo server**: URL, header and the public shared secret are hard-coded in `core/config.py` (same values in all ONLYOFFICE connectors).
  The 30-day trial starts on first enable and is stored in the portal annotation `onlyoffice.plone.demoStart`.
- **`docUrlPublicValidation`** is a hidden checkbox: control panel JS loads `api.js` from the public Docs URL in the browser
  and ticks it if that worked; the server refuses to save settings otherwise. Volto always sends `true`.
- **Internal URLs**: `docInnerUrl` is used for Plone → Docs; `ploneUrl` for Docs → Plone.
  `replaceDocUrlToInternal` rewrites the public Docs URL in the callback result URL to the internal one.
- **`shardkey`** (document key) is added to `api.js` and `converter` URLs so a Docs cluster routes all requests of one document to one node.
- **Volto contract**: the editor mode is passed as a path suffix (`/path/file.docx-onlyoffice-edit`) because the service
  reads the path via `publishTraverse`. Must match the regexp in `onlyoffice-volto/src/components/Views/OnlyofficeEditor.jsx`.
- REST POST services disable CSRF protection (`IDisableCSRFProtection`).
- REST `SettingsSave` in demo mode **writes the demo URL and demo secret into the registry**; the Classic control panel does not.
- The "Create with ONLYOFFICE" menu adapter is registered globally in ZCML; `setuphandlers.post_install/uninstall`
  also (un)register it in the site manager (commit 201613e, "only on current site"). The guard that actually hides it on
  sites without the add-on is `OnlyofficeCreateSubMenuItem._is_addon_available()`. Keep both when touching install code.
- plone.rest service views are named `<METHOD>_application_json_<name>` (e.g. `GET_application_json_@onlyoffice-volto-get-config`);
  that is how `tests/test_smoke.py` looks them up.

## 6. Known issues and tech debt

**Security:** notes from the code review done for this handover were passed on separately, outside this
public repository. Ask the team lead for them before changing token handling or URL fetching code.

**Bugs / leftovers:**
- No timeouts on `urlopen` / `requests` (callback, conversion, validation) — a slow Docs can block Zope workers.
- `controlpanel.py:handleSave` logs `logger.error("SAdfasdf")` on every save.
- `conversionUtils.convert`: `"…" + response.status_code` (str + int) raises inside `try`, so users see "cannot be reached" instead of the HTTP status.
- `OInsert` sets 401 for anonymous users but continues processing.
- `fileUtils.getFileExt`: `UnboundLocalError` for types other than File / Document / Image.
- Editor page version check (`view.pt`) still says Docs > 6.0 is enough (see section 1).
- Deprecation warnings: `datetime.utcnow()`, `logger.warn`.

**Infrastructure:**
- `tox.ini` uses `-s onlyoffice-plone` (should be `onlyoffice.plone`), so `tox -e test` finds no tests. CI runs no tests
  (lint and licenses only).
- `CONTRIBUTING.md` says `pip install -e .[dev]`; there is no `dev` extra (`test` exists).
- `z3c.jbot==2.0` pin conflicts with Plone constraints (section 3).
- `setup.py` classifiers (Plone 6.1, Python ≤ 3.11) do not match the tox matrix.
- `metadata.xml` is `4010`, but the only upgrade step is 1000 → 2000.
- `master` has `chore: add GitHub issue templates` that is not merged into `develop`;
  `develop` has submodule bumps made after 4.1.0.
- Tests: `test_setup.py` was written for the Plone 5 installer API (fixed in this branch); the robot test is the
  template login example.

**Unmerged branches (left as they are):**
- `feature/theme` (2025-10, 1 commit): light editor theme by default (`uiTheme: default-light`).
- `feature/rename` (2021): module renames, 249 commits behind `develop`.
- `temp/stand` (2025-04): stand for the first Volto REST API; that code is in `develop` already.

### Manual checklist (things not automated)

Run on the local stand, Classic UI, a Manager and a second user with the Editor / Reviewer / Reader role:

1. Settings: save with a wrong Docs URL → "ONLYOFFICE cannot be reached"; wrong secret → "Authorization error"; correct values → saved.
2. Demo: tick "Connect to demo ONLYOFFICE Docs server" → saved; the editor shows the demo warning.
3. Create each type from "Create with ONLYOFFICE" in a folder → the editor opens; site language ≠ English → the template is localized.
4. Edit a DOCX, type text, close the tab, wait ~10 s → reload the file page: content saved, a new editor session shows the change.
5. Two browsers on the same file → co-editing works, changes saved once both close.
6. Reader: only "ONLYOFFICE View", editor read-only. Reviewer without modify: "ONLYOFFICE Review", track changes forced.
7. PDF form: "Fill in form in ONLYOFFICE" → fill, close → values saved in the PDF.
8. Download as: DOCX → PDF and ODT; file downloads.
9. Conversion in ONLYOFFICE: ODT → DOCX created next to the source and opened in the editor.
10. In the editor: Save copy as (to a folder), insert image from Plone, compare with a file from Plone, mail merge source from Plone.
11. "ONLYOFFICE View" as the display view of a File.
12. Uninstall the add-on → actions and menu disappear; reinstall works.
