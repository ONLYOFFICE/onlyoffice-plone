# onlyoffice.plone

Plone 6 backend add-on that connects Plone to ONLYOFFICE Docs (Document Server).
Serves both Classic UI (browser views + `.pt` templates) and Volto (REST services used by
the `@onlyoffice/volto` add-on, repo `onlyoffice-volto`). Background, history and gotchas: `HANDOVER.md`.

## Commands

```bash
git submodule update --init --recursive        # REQUIRED: formats table + new-file templates
pre-commit run -a                              # lint (black, isort, flake8, zpretty, codespell, check-manifest, i18ndude)
python -m build                                # sdist; CI removes .git/.gitignore/.gitmodules first so submodule files are packed
```

On Windows set `PYTHONUTF8=1` for pre-commit / build: `setup.py` reads `README.md` without an encoding and fails on cp1251.

Tests (no Docs needed; Docker, Plone 6.1). `tox -e test` is broken (`-s onlyoffice-plone` in tox.ini), use:

```bash
docker run --rm -v "$PWD:/mnt/repo:ro" plone/plone-backend:6.1 sh -c '
  cp -r /mnt/repo /tmp/pkg && cd /tmp/pkg &&
  /app/bin/pip install -q -c /app/constraints.txt zope.testrunner plone.app.testing plone.app.robotframework robotsuite &&
  /app/bin/pip install -q -e . &&
  /app/bin/zope-testrunner --test-path=/tmp/pkg/src -s onlyoffice.plone'
```

(Git Bash on Windows: prefix with `MSYS_NO_PATHCONV=1` and use `$(pwd -W)`.)
`pip install -e .` must run WITHOUT Plone constraints: `z3c.jbot==2.0` in setup.py conflicts with them.

End-to-end check against a live Plone + Docs: `src/onlyoffice/plone/tests/stand_smoke.py`
(env vars in its docstring; stand setup in `HANDOVER.md` → "Local stand").

Dev run: `docker run -p 8080:8080 -e SITE=Plone -e PROFILES=onlyoffice.plone:default -e DEVELOP=/app/src/onlyoffice.plone -v "$PWD:/app/src/onlyoffice.plone" plone/plone-backend:6.1 start`

## Layout

- `core/` — no Plone views: `utils.py` (JWT, doc key, URLs, demo), `config.py` (registry + demo server constants), `conversionUtils.py` (Conversion API), `fileUtils.py`, `formatUtils.py`
- `browser/actions.py` — editor pages (`get_config` builds the Docs editor config), convert / download-as forms
- `browser/api.py` — endpoints Docs and JS call: `onlyoffice-callback`, `onlyoffice-dl`, create, save-as, insert, conversion
- `browser/controlpanel.py` — settings + validation against Docs (healthcheck, CommandService, ConvertService)
- `browser/templates/view.pt` — editor page JS (Classic UI), `browser/static/js/*`
- `restapi/` — `@onlyoffice-volto-*` services for Volto
- `browser/app_data/` (submodule `document-templates`), `browser/document-formats/` (submodule `document-formats`) — never edit in place
- `profiles/default/` — GenericSetup (registry, actions, type views); `upgrades.zcml` — upgrade steps
- `tests/test_smoke.py` — main-feature smoke tests, Docs calls mocked

## Conventions

- Lint/tox/pre-commit/gitignore files are generated by `plone/meta`; change settings in `.meta.toml`, not by hand.
- Branches: `develop` → PR `Release/x.y.z` → `master`. Feature branches `feature/*`, `fix/*`. Commits: conventional (`feat:`, `fix:`, `chore:`, `ci:`).
- Version lives in 3 places: `setup.py`, `profiles/default/metadata.xml` (`4.1.0` → `4010`), first entry of `CHANGELOG.md` (CI tags from it).
- License header (`(c) Copyright Ascensio System SIA <year>`) on every source file.
- New user-facing strings: `_()` from `onlyoffice.plone.interfaces`, then update `locales/` (`update_locale`).

## Do not

- Do not change `getDocumentKey` or replace `reindexObject()` in `Callback` with an index list — the key must change on every save, otherwise Docs serves a cached old version.
- Do not change the `-onlyoffice-<mode>` path suffix parsing in `restapi/get.py` without the matching change in `onlyoffice-volto`.
- Do not change demo server constants in `core/config.py` — they are shared by all ONLYOFFICE connectors.
- Never commit secrets (JWT secrets, PyPI tokens). Publishing uses PyPI trusted publishing (OIDC), no token in the repo.
- Do not commit submodule pointer bumps by accident (`git status` shows `browser/app_data` as modified after switching branches — run `git submodule update`).
